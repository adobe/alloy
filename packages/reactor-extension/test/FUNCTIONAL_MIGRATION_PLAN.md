# Functional (TestCafe) → Vitest Migration Plan — reactor-extension

Ticket: PDCL-13402. Goal: retire the TestCafe suite in
`packages/reactor-extension/test/functional` in favor of Vitest browser mode
(Playwright Chromium) + MSW, which already runs on GitHub Actions via
`pnpm run test` (`reactor-extension/integration` project in
`packages/reactor-extension/vitest.projects.js`). TestCafe is not run in CI
today.

Status: **spike in progress** (2026-11-24). Counts below are as of
`origin/main` 29d6da116.

## Why the TestCafe suite cannot be the parity oracle

The TestCafe suite has not run in CI and has drifted from `src/`:

- `extensionViewController.init()` always fetches a real Adobe IO/IMS token
  (`EDGE_E2E_CLIENT_SECRET`), so every view spec needs credentials and network,
  regardless of the `requiresAdobeIOIntegration` meta flag.
- `expectSettings` assertions omit `dataElementName`, which the current views
  emit; override tests drive removed UI (datastream input-method radio,
  freeform datastream field, sandbox picker).
- Component specs assert Spectrum v3 class names and `Heading` props
  (`variant`, `isSerif`) that no longer exist.
- `view/configuration/configuration.spec.mjs` calls controller methods that do
  not exist (`saveSettings`, `isValid`) on the wrong port.
- Some assertions are no-ops (`expectError` without `()` in sendEvent, missing
  `await`s in the key-value / JSON editor specs, duplicate tests).

Migration therefore ports the **behavior** each TestCafe test describes,
asserted against current `src/`, not the literal TestCafe expectations. Where a
TestCafe expectation is stale, the Vitest test asserts the current behavior and
the crosswalk notes it.
